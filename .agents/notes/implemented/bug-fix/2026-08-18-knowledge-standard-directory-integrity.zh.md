# Agent Note: 保持知识库标准目录完整性

Status: implemented

[English](2026-08-18-knowledge-standard-directory-integrity.md) | 中文

## 问题

JiMu 只有在 Schema 1 的全部核心目录和本机已启用按需模块目录都存在时，才会接纳已有 Markdown 根目录。旧校验把末段为符号链接的路径一律当成缺失目录，其中包括一种常见的本地布局：`assets` 指向同一知识库内另一处规范媒体目录。选择这类有效的 legacy 根目录时，即使目标真实存在且没有离开知识库，仍会报“知识库缺少标准目录：assets”。

内置空白模板还以另一种方式破坏了同一条不变式。模板用 `.gitkeep` 表示空协议目录，而 Electron Builder 在复制 `extraResources` 时会过滤这些占位文件。准备完成的构建缓存结构完整，打包后的应用却静默缺少那些没有其他文件的目录。源码阶段的压缩包校验和内容扫描都观察不到目录项，因此旧发布审计没有拦住不完整的应用。

## 决策

已有根目录检查接受真实必需目录，并只为 `assets` 提供一种有界别名形式：真实目标仍是知识库真实根目录内目录的符号链接。校验先解析根目录，再解析链接后的资产路径，执行路径感知的包含关系判断，最后确认目标类型。内容分类目录仍须为真实目录，避免索引采用的物理路径与逻辑分类路径分离。缺失必需路径、资产断链、资产目标不是目录或资产链接越出根目录，仍是不兼容状态，并给出相互区分的诊断。该兼容规则只读取已有根目录，不添加 Manifest，也不修改用户布局。按需模块选择由 [JiMu 原生首次配置](../feature/2026-08-18-jimu-native-first-run-setup.md) 持有。

打包的完整模板保持更严格的边界，只允许真实目录。macOS `afterPack` 钩子先确认复制后的模板 Manifest 存在，再重建该完整模板中被 Electron Builder 省略的全部目录，并验证结果是非符号链接的真实目录。发布审计会定位打包模板的 Manifest，并直接检查目录项；缺少 Manifest、缺少目录或目录为链接都会让发布闸门失败。

## 备选方案

**拒绝所有标准目录符号链接。** 未采用，因为它会阻止通过库内 `assets` 链接复用媒体的有效本地知识库。对于这个非内容别名，真正的安全边界是解析后的目录是否仍位于用户选择的根目录内，而不是末段是否为链接。

**跟随所有标准目录符号链接。** 未采用，因为不可信或意外变化的知识库可以把索引和资产访问重定向到用户所选目录之外；即使内容分类链接留在库内，也会让它的逻辑分类路径与物理索引路径分离。只有 `assets` 获得有界例外；内容分类仍须为真实目录，越界、断链和非目录资产目标也仍会被拒绝。

**替换用户链接或复制其数据。** 未采用，因为选择已有根目录属于只读验证。JiMu 不应只因打开 legacy 仓库就改写它、复制可能很大的媒体或让 Git 工作区变脏。

**提交可见占位文件，而不是修复安装包。** 未采用，因为配套 Knowledge 协议有意让业务目录保持为空。空目录结构应由打包流程保留，发布审计应检查最终交付物，而不是为了适应打包器过滤规则而修改源码协议。

## 影响

已有根目录可以保留库内 `assets` 别名，包括指向自媒体工厂媒体目录的相对链接；没有 Manifest 时仍会被识别为 `legacy-schema-1`。指向用户所选根目录外的链接不会扩大 JiMu 的读取权限，用户知识库也不会被修改。

即使 `.gitkeep` 被过滤，JiMu.app 也会携带完整空白模板中的全部目录。未来同类打包回归会同时被定向安全测试和发布物审计拦截。测试覆盖库内链接、越界链接、断链、文件目标、打包后目录恢复和发布审计强制执行。
