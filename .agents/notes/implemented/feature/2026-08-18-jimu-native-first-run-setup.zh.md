# Agent Note: JiMu 原生首次配置

Status: implemented

[English](2026-08-18-jimu-native-first-run-setup.md) | 中文

## 问题

新安装尚未选择知识库布局或配置可用的 DeepSeek 凭据时，JiMu 就会暴露知识库、工厂和 Agent 工作区。空白模板操作还要求用户自行选择父目录，并假设发布物中的每个目录都必须存在，即使用户完全不需要对标博主库或自媒体工厂。已经填写但无效的 Key 只有在第一次提示词发送后才会失败，导致本地配置看似完成，Agent 实际却不能运行。

## 决策

Electron 产品持有一份原生、带 revision 的首次配置状态；只有按需模块已经选择、本地知识库根目录已经验证并激活、DeepSeek 凭据已经通过认证模型发现，主工作区才会开放。首次配置完成是一项持久事实，不由服务的瞬时健康状态推导。完成后，知识库初始化、模块调整、Harness 重启和凭据可用性变化都留在主工作区内处理；只有明确重置才会重新打开首次配置。对标博主库与自媒体工厂默认开启，但彼此独立。启用状态只保存在权限为 `0600` 的桌面设置文件中，不进入知识库仓库；关闭的目录既不要求存在，也不进入索引，关闭的工厂不会启动服务。关闭从不删除内容。重新启用缺失模块时，JiMu 必须先取得用户确认，再从打包模板原子复制空目录骨架。

默认知识库安装只使用 `knowledge-template-lock.json` 中固定的 GitHub Release URL 和 SHA-256。下载发生在有界的私有临时目录中，只接受确定性构建所用的 stored-ZIP 编码，拒绝路径逃逸和超大输入，过滤关闭模块的子树，完成验证后再原子重命名。下载或 Release 校验失败时，应用使用安装包内同版本模板，并显示实际来源。已有目标永不覆盖；默认目标若已经是兼容知识库，则按已有根目录连接。

凭据验证属于 DeepSeek 适配器在 `llm-deepseek` 下注册的模型发现。它调用解析后端点的认证 `GET /models`，拒绝跳转，限制响应体和超时，并且只返回模型 id。草稿 Key 通过既有的只写发现请求传递，只有发现成功后才进入 `credentials.set`。环境变量或托管存储中的 Key 可以在适配器内部解析并验证，不会回传给 Electron 或 Renderer 状态。

## 备选方案

**保留旧知识库设置卡，让 Agent 提示词按需失败。** 未采用，因为三条分散的恢复路径会让尚未完成必需服务的新安装看起来已经可用，而且凭据错误要等用户输入任务后才出现。

**把模块选择写进 `jimu-knowledge.json`。** 未采用，因为同一仓库在另一台设备上打开时会产生未提交改动，而且设备偏好不应成为可移植内容协议的一部分。

**为每种模块组合发布一份知识库压缩包。** 未采用，因为四个资产会带来不必要的发布和校验摘要漂移。一份经过审查的完整压缩包可以在临时目录解压时安全过滤。

**通过聊天补全测试 Key。** 未采用，因为连接配置不应提交会话内容或消耗生成 Token。认证模型列表接口可以在不发起模型请求的前提下验证凭据和端点。

## 影响

新用户会进入统一的 JiMu 三步流程，并能通过一次选择接受完整默认配置。源码运行时，默认知识库位于 Harness 仓库同级；打包应用使用 `~/JiMu-Knowledge`。中断后的配置会从已持久化的模块和根目录状态继续，而凭据只有测试成功后才视为完成。运行期模块调整保持设置页挂载，并通过对应控件显示进度，不会用首次配置页面替换应用。

公开 Schema 1 仍支持八个分类，但必需目录由核心目录加本机启用模块共同决定。JiMu-Knowledge 官方 Release 仍携带完整空目录树。测试覆盖可选根目录校验、关闭目录不索引、有界安装和回退、模块骨架创建、凭据认证与错误脱敏，以及 Electron 首次配置阻断。
